# MDSE Ruleset

Status: **v2.0-draft**, migrated 2026-10-19 from the owner-reviewed Rules Register. This is the only ruleset. Pre-migration sources (Ruleset 1.23, the Workspace Decision Log W-01 to W-398, the V2 ADRs and contracts) are history; their surviving rules are below with their origin in brackets.

## How to read a rule

`- **ID** · Status · Phase [· live] — rule. (origin)`

- **ID** is permanent. A retired ID is never reused.
- **Status:** `Active` (binding) · `Proposed` (not yet approved) · `Check` (owner-reviewed but a later decision changed part of it; the note says what) · `Unreviewed` (carried from the register, not yet reviewed by the owner; not binding).
- **Phase:** `Standing` (always applies) · `P1` EA import, Base Vault, Bootstrap, read-only Workbench · `P2` BOM import, merge and approval · `P3` Workbench editing · `Later`.
- **live:** an optional tag after the Phase. It marks a rule that is new or changed since the live vault's documentation was last updated, so the documentation updates can be found (filter the Live column of `governance/register/rules-register.csv`). It is added with the rule or the change and removed once the live documentation is updated. It has no effect on whether the rule binds. (D-0045)
- **Origin:** REG-nnn is the register row; W-nnn, V2-nn, R-n.n, D-nnnn are the decisions behind it.
- To change a rule: add a decision to `DECISIONS.md`, edit the rule here in the same commit, and move retired rules to the Retired section. `npm run check:rules` enforces the format.

## GOV — Governance and change control

### Governance

- **GOV-001** · Active · Standing — Changes are pushed directly to `main`. Every push must leave CI green; a red `main` is fixed before any other work. (D-0005)
- **GOV-002** · Active · Standing — Tools are written in TypeScript and share one core library. Python and Java are used only for CI oracles and the SysML v2 parser gate; users never run them. (D-0007)
- **GOV-003** · Active · Standing — A rule with status Unreviewed is visible but not binding. No build work may depend on an Unreviewed rule until the owner sets it to Active. (D-0008)
- **GOV-004** · Active · Standing — Rules live in `governance/RULESET.md` only. Decisions that create, change or retire a rule are recorded in `governance/DECISIONS.md` and name the rule they change. (D-0006)

## DAT — Data and security

### Relationships

- **MOD-073** · Active · P1 — There is no provisional relationship field. A link whose relationship cannot be resolved is recorded as a `flagLink`. (D-0010)
- **MOD-074** · Active · Standing — supersedes/supersededBy is kept for elements replaced by another note. Nothing in the import writes it. (REG-020, W-191)
- **MOD-075** · Active · Standing · live — For a SysML v2 relationship, legal endpoints and ownership come from the native SysML construct and its typed model, not from `relationships.yaml`; the authoritative `## SysML v2` block is validated independently. Endpoint restrictions (`from`, `to`, `sameClass` and exclusions) in `relationships.yaml` apply only to relationships explicitly approved as MDSE-only YAML links. Until OD-01 completes the field-by-field split, V1 entries in that schema do not authorize, prohibit or duplicate native SysML relationships. (REG-021, W-272; D-0003, D-0061, D-0069)
- **MOD-076** · Active · Standing · live — For native SysML v2 relationships, Workbench and importer read the forward meaning from the authoritative `## SysML v2` block and derive reverse navigation from it; no SysML-defined inverse is persisted in YAML.
